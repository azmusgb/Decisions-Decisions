# GET THE POINT — Repository Product Truth

Updated: 2026-09-07

This file exists to stop historical prototype code and creative-direction artifacts from silently overriding the current product.

## LOCKED

- Core differentiator: **choice under time pressure**.
- One prompt presents multiple communication routes with prompt-specific points.
- The active player chooses a route before performing.
- Commitment is irreversible once clueing begins.
- Teammates guess while the timed turn is active.
- Correct guesses earn the selected route's points.
- Content/packs should expand the game without creating separate mechanics forks.
- No subscription by default.
- Digital core play should be offline, pass-and-play, local-first, and require no unnecessary permissions.

## v2.1 CHALLENGER — PROPOSED / NEEDS PLAYTESTING

- Method presentation: **HUM → DRAW → MIME**.
- Method signals: **teal HUM / yellow DRAW / purple MIME**.
- HUM icon: musical note.
- DRAW icon: marker/pencil.
- MIME icon: theatrical-mask direction; comprehension still needs testing.
- Method controls are approximately 10–15% larger than the prior prototype.
- Digital interaction: **one tap = select + commit**; no second confirmation step.

## SMART-CARD UX CHALLENGER — PROPOSED / NEEDS PLAYTESTING

- Active gameplay should feel like a stack of smart cards rather than a dashboard.
- The prompt remains the dominant element during both choice and performance.
- Visible `LOCKED` / `COMMITTED` ceremony is intentionally minimized or removed from normal play.
- Removing the ceremony does **not** remove the underlying irreversible commitment rule.
- A deliberate right-swipe after a correct guess may score the already-selected prompt-specific points and advance immediately.
- The existing Correct control remains as an accessible/failsafe scoring path while the swipe interaction is tested.
- DRAW must protect canvas/tool gestures from accidental scoring swipes.
- Live score may be visually suppressed during the timed turn and shown at natural breaks/results.
- Swipe-to-score, reduced active-turn chrome, and hidden live score are interaction challengers, not settled commercial behavior.

## TEST BASELINE — NOT FINAL COMMERCIAL RULES

- Round timing: **60 sec → 30 sec → 15 sec**.
- 15-second tiebreak remains a baseline to test.
- Current PWA exposes timer-start timing as a test condition rather than hiding it in code.

## CONTENT RULES

Every core prompt should be evaluated for:

- representability across active routes
- clear target
- audience/cultural fit
- scoring balance
- no accidental giveaway
- rights safety

Point values in prototypes are estimates until calibrated with playtest evidence. Remove weak prompts rather than padding deck size.

Prompt format is **not** permanently locked to exactly one word. The current candidate pool is one-word-heavy because it is useful for testing representability and speed.
